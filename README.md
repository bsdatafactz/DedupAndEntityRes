# Deduplication and Entity Resolution (Medallion Architecture)

A learning project for a financial services use case, built with Python and PySpark in local mode.

**Use case:** a fictional bank, Meridian Trust, keeps customers in three systems (core banking, credit card, loan). The same person appears under different spellings and formats, sometimes twice in one system. The pipeline links those records and produces one best record per real person.

All data is synthetic, generated by `src/01_generate_data.py` (including fake SSNs).

## Design

| Layer | Table | Key | Purpose |
|---|---|---|---|
| Bronze | raw records | `bronze_id` | Exactly as received, never changed |
| Silver | cleaned and linked | `silver_id`, `bronze_id`, `entity_id` | Standardized columns plus the match result. One row per bronze row, nothing deleted |
| Gold | best record per person | `gold_id`, `entity_id` | One row per real person, with `silver_ids` and `bronze_ids` for tracing back |

Bronze to silver is one to one. Silver to gold is many to one.

## Pipeline

| Step | File | Output |
|---|---|---|
| 1 | `src/01_generate_data.py` | `data/raw/bronze_raw.csv`, `data/raw/ground_truth.csv` |
| 2 | `src/02_bronze.py` | `data/bronze/` (Parquet) |
| 3 | `src/03_silver.py` | `data/silver_clean/` (standardized) |
| 4 | `src/04_silver_match.py` | `data/silver/` (adds `entity_id`, `match_rule`) |
| 5 | `src/05_gold.py` | `data/gold/` |
| 6 | `src/06_evaluate.py` | precision, recall, F1 against the ground truth |
| 7 | `src/07_publish.py` | Postgres tables and CSV exports in `data/exports/` |

**Matching:** block on date of birth, then apply rules in order (same SSN; same phone and last name; same email; close first name with same last name and ZIP). Matched pairs are clustered with union-find.

## Results (synthetic data, 2,091 records)

| Metric | Value |
|---|---|
| Entities found | 1,100 |
| Real people | 1,100 |
| Precision / recall / F1 | 1.00 / 1.00 / 1.00 |

The score is perfect partly because the injected noise is mild. Harder data (typos in last names, wrong birth dates) is the next test.

## Run it

Requires Java 17 and Python 3.10 to 3.13 (PySpark does not support 3.14 yet).

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python src/01_generate_data.py
python src/02_bronze.py
python src/03_silver.py
python src/04_silver_match.py
python src/05_gold.py
python src/06_evaluate.py
```

Run every command from the project root.

### Optional: Postgres

Create a database named `meridian` with schemas `bronze`, `silver`, `gold` and `eval`, then:

```bash
python src/07_publish.py
psql meridian -f sql/01_keys.sql     # primary and foreign keys
psql meridian -f sql/02_practice.sql # practice queries
```

More detail on the concepts, challenges and testing is in `docs/project_notes.md`.
